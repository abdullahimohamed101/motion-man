# Native G0–G1: hardware baseline and RT-DETR TensorRT feasibility
Status: Active (P4 merged, PR #13) · Branch: `feat/native-g0` · Spec: C§2–C§6, ADR-001..003

## Outcome
The owner's NVIDIA PC has one pinned, supported CUDA/TensorRT stack proven by a real CUDA smoke test (G0). A
pinned RT-DETR checkpoint is exported to ONNX, built into a TensorRT FP32 engine, and run from C++ with detections
matching the FP32 PyTorch reference within C§6 gates (G1). The Mac builds and tests the portable C++ core.

## Non-goals
- Video decode, tracking, rendering or records in C++ (G2). FP16 (G3). Multistream (G4). Remote jobs (G5).
- Any speed claim. Engine build time and one-image latency are recorded as observations, not benchmarks (ADR-002).
- Changing INV-1 (ADR-004 waits for G4) or the Python pipeline. UI changes.

## Decisions
- D1 G0 and G1 are one plan with a hard stop after step 5 (G0 gate) for the owner's go-ahead.
- D2 Steps say where they run: **[Mac]**, **[PC]**. A [PC] result is recorded only from PC output; never from the Mac.
- D3 Linux vs WSL2 and every toolkit version are chosen in step 3 from the inventory, recorded as ADR-005.
- D4 No C++ test framework download: portable tests use plain `assert`-style checks registered with CTest.
- D5 System installs (driver, CUDA toolkit, TensorRT, OpenCV dev, CMake) are run by the owner with `sudo`;
  I give exact commands and record versions. Downloads (RT-DETR repo, checkpoint) wait for the owner's yes.
- D6 Engine build in G1 uses TensorRT's own `trtexec` wrapped by `tools/model_export/build_engine.py`, which
  writes the engine, `engine_manifest.json` and the full build log. A native builder can replace it later.
- D7 Golden images: 8 frames from the owner's crosswalk clip (indices fixed in `configs/reference/`) plus
  synthetic portrait, landscape and pattern images generated by a script. Images stay out of git; hashes don't.
- D8 Model artifacts live under `~/.cache/motionman/models/<profile>/` on the PC, never in the repo.

## Steps
1. [x] **[Mac]** Portable C++ skeleton: `native/CMakeLists.txt`, `CMakePresets.json` (`mac-cpu` without CUDA
   discovery; `linux-cuda-release` that fails if CUDA/TensorRT are missing), `native/include/motionman/` frame
   key and detection types, `native/tests/unit/` with a CTest target. Needs `brew install cmake` (owner's yes).
2. [x] **[Mac]** Reference fixtures: `configs/reference/inputs.json` (clip SHA-256s, golden frame indices),
   `tests/fixtures/source_time.json` shared by a pytest and a C++ unit test so both languages round `source_t_us`
   identically (C§8). Record H0: the validated Python run `ed3f02` id, records hash and settings.
3. [x] **[PC]** Inventory into `docs/environment.md`: GPU, compute capability, VRAM, OS/WSL, driver, `nvcc`,
   TensorRT, compiler, CMake, OpenCV, disk, power. Choose Linux or WSL2 and the version set; ADR-005.
4. [ ] **[PC]** Owner installs the pinned stack (D5). Checkout via `git clone` over SSH; record commit.
5. [ ] **[PC]** CUDA smoke test `native/tests/gpu/cuda_smoke.cu`: device query plus a vector add on a non-default
   stream, every return code checked, label `gpu`. `ctest --preset linux-cuda-release -L gpu` passes and its
   output plus host summary go to `docs/environment.md`. **G0 gate: stop for the owner.**
6. [ ] **[PC]** `tools/model_export/`: pinned RT-DETR clone and checkpoint (D5), upstream ONNX export with deploy
   postprocessor, generated `manifest.json` (hashes, commit, opset, actual tensor names/dtypes/shapes, classes,
   licence). R0: PyTorch FP32 detections on the golden images with the TF32 policy recorded.
7. [ ] **[PC]** Preprocessing contract `configs/native/rtdetr_r18_640.json` and golden-tensor check: C++ OpenCV
   preprocessing vs the Python reference transform (C§6 layout and resize gates). ONNX Runtime vs R0 parity.
8. [ ] **[PC]** `build_engine.py` (D6): TensorRT FP32 engine, `engine_manifest.json` with full identity (C§5),
   build log and build time. A mismatched manifest refuses to load.
9. [ ] **[PC]** `native/src/gpu/`: RAII engine, context, stream, device/pinned buffers and events;
   `motionman-native infer --profile … --images …` writes detections JSON. Parity test (label `gpu`) vs R0:
   ≥ 99% same-class matches at IoU 0.99, score error ≤ 0.005, zero non-finite outputs.
10. [ ] **[Mac]** G1 write-up: acceptance results, ADR-003 Accepted or superseded, G2–G6 re-estimate, STATE.
   **G1 gate: stop for the owner.**

## Risks
- GPU, driver or OS outside TensorRT's support matrix: G0 fails; choose another version set or host (C§4).
- WSL2 limits (pinned memory, telemetry) make some measurements unavailable: record them null, never zero.
- RT-DETR export needs an unsupported op or plugin: stop at step 6/8 and revisit ADR-003 before going further.
- Mac `mac-cpu` and PC builds drift: the commit is the sync unit (C§4); the PC records what it built.
- Estimate: G0 1–2 focused days, G1 2–4 (NA§16), re-estimated at step 10.
